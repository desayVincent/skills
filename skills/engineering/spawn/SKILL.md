# 按任务分工

默认由主代理完成。分工必须减少实际工作量，而不是增加协调步骤。
宿主或项目规则决定模型、角色名称和执行权限；本 skill 不绑定厂商或 API。
一次连贯的小改动、几次工具调用即可完成的任务，直接做。

## 判断是否独立

并行实施前，确认以下条件：

- 至少有两个有独立结果和验证方式的任务；任务规模值得分派。
- 不修改同一文件，包括测试、生成文件和共享配置。
- 没有先后依赖，也没有尚未约定的共享接口。
- 不争用板卡、串口、JTAG、构建目录、服务实例等共享资源。
  只有板端验证冲突时，可并行编码、串行上板；在任务说明中写清资源使用顺序，
  子代理不能擅自复位或占用共享设备。

多个文件报错不代表多个根因。先检查公共依赖；可能同源的故障一起调查。
无法确认独立时，先由主代理定位。

## 选择角色

| 任务 | 执行者 |
| --- | --- |
| 单次查找、小改动、边界不明或需要综合裁决 | 主代理 |
| 有范围的只读代码梳理 | 只读子代理 |
| 明确的实现和测试任务 | 实施子代理 |
| 合并结果、判断遗留风险、最终交付 | 主代理 |

使用宿主提供的对应能力，并遵守项目已有模型策略。没有子代理能力时顺序执行，
如实说明执行方式。只读角色不能修改被分析源码；实施角色是叶子，不再分派。

## 分派与返回

为每个任务给出：目标、已知事实与待验证问题、允许读写的路径、禁止事项、
共享资源约束、完成条件和验证命令。只提供必要上下文；支持时使用独立上下文。
互相独立的任务同时发出；遇到新依赖或越界需求，子代理返回主代理处理。

子代理返回实际修改、根因或实现说明、运行过的命令与结果，以及未验证事项。
不因分派而新增提交、推送、安装或外部操作权限。

## 主代理收尾

检查实际 diff 和测试证据，确认没有越界改动、冲突或接口不一致。
各任务分别通过后，运行覆盖它们交互的集成检查；按风险确定范围，
不机械要求全仓测试。未解决问题和无法执行的检查保留在交付说明中。
只有组合结果有对应证据时，才声明任务完成。
