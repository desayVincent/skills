# 按任务分工

默认由主代理完成。分工必须减少实际工作量，而不是增加协调步骤。
宿主或项目规则决定模型、角色名称和执行权限；本 skill 不绑定厂商或 API。
一次连贯的小改动、几次工具调用即可完成的任务，直接做。
主代理负责最终判断和交付；本 skill 组织执行，不新增全局自动审核触发条件。

## 选择执行分支

- 实施或调查：先判断委派收益。单个任务可委派，不要求为了分工再拆出第二项；
  说明具体可减轻的工作或所需专业检查，收益不足则自行完成。
- 独立审核：用户或适用规则要求时，直接进入下文「独立审核」，不受并行实施门槛限制。
- 并行实施：通过下列独立性检查后才分派。

## 判断是否独立

并行实施前，确认以下条件：

- 至少有两个有独立结果和验证方式的任务；任务规模值得分派。
- 不修改同一文件，包括测试、生成文件和共享配置。
- 没有先后依赖，也没有尚未约定的共享接口。
- 不争用板卡、串口、JTAG、构建目录、服务实例等共享资源。
  只有板端验证冲突时，可并行编码、串行上板；在任务说明中写清资源使用顺序，
  子代理不能擅自复位或占用共享设备。

多个文件报错不代表多个根因。先检查公共依赖；可能同源的故障一起调查。
无法确认独立时，先由主代理定位。

## 选择角色

| 任务 | 执行者 |
| --- | --- |
| 单次查找、小改动、边界不明或需要综合裁决 | 主代理 |
| 有范围的只读代码梳理 | 只读子代理 |
| 明确的实现和测试任务 | 实施子代理 |
| 有范围的研究 | 只读研究子代理 |
| 合并修改及交互验证 | 主代理，或委派给集成子代理 |
| 独立审核 | 未参与目标修改的只读审核子代理 |
| 判断遗留风险、最终交付 | 主代理 |

使用宿主提供的对应能力，并遵守项目已有模型策略。没有子代理能力时顺序执行，
如实说明执行方式。只读角色不能修改被分析对象；子代理均为叶子，不再分派。
缺少独立审核能力时，不以主代理自查冒充独立审核，按下文记录缺口。

## 分派与返回

为每个任务给出：目标、已知事实与待验证问题、允许读写的路径、禁止事项、
共享资源约束、完成条件和验证命令。只提供必要上下文；支持时使用独立上下文。
互相独立的任务同时发出；遇到新依赖或越界需求，子代理返回主代理处理。

子代理返回实际修改、根因或实现说明、运行过的命令与结果，以及未验证事项。
不因分派而新增提交、推送、安装或外部操作权限。

## 主代理收尾

检查实际 diff 和测试证据，确认没有越界改动、冲突或接口不一致。
各任务分别通过后，运行覆盖它们交互的集成检查；按风险确定范围，
不机械要求全仓测试。未解决问题和无法执行的检查保留在交付说明中。
只有组合结果有对应证据时，才声明任务完成。

## 独立审核

在完整任务的最终修改和自检完成后，安排一次独立审核；不要按文件、保存次数或每轮对话重复启动。
用户或领域规则要求的设计前置审核仍按其时点执行。同一范围、同一最终版本已有合格独立审核证据时复用，不再重复。
审核后仅有无语义的文字或排版改动时，主代理核对增量并补充自查记录，即可沿用原审核；行为或合同变化不适用。
审核者必须未参与目标修改；主代理的自查、实施者或参与修改的集成者不能充当该目标的独立审核。

交给审核者：任务目标及验收条件、修改前基线与最终 diff、涉及的文件、必要的适用规则和已有验证结果。
默认不传整段会话或要求全仓扫描；审核者可按具体疑点补读直接依赖，并说明扩大读取的理由。
领域检查项使用适用领域 skill，本 skill 不复制其清单。禁止修改目标、继续委派或授权提交、推送等外部操作。

审核返回：问题严重性、文件位置、依据、影响及建议；无发现时说明覆盖范围和未验证项，不能把未检查当作通过。
主代理核实意见，修复确认的问题；有分歧时记录证据和处置理由。
修复后仅复核原问题及受影响范围；新改动改变目标、合同或扩大风险时，才重新完整审核。
未修复的阻塞问题不得标记通过；无法独立审核时说明原因、已完成的自查及缺口，不声明审核完成。

完成条件：最终版本有对应审核证据，问题均有处置，必要复核已完成。
在现有任务记录或交付说明中简记审核范围、结论和未验证项，不为每个小任务新建报告体系。
