# 写作语义验证

`semantic-cases.json` 包含输入、授权、保留点、禁止变化及本次实际输出，覆盖设计、性能、复盘、全文更新、好句保留、约束、机器内容、校对、只读审阅、API、UI 和操作。案例由本次维护者构造，输出由主会话模型实际整理；不是独立生成的对照实验，不能据此计算新旧版本胜率。

## 重跑

在干净会话加载 SKILL.md 及路由参考，仅提供案例的 task 和 input，不提供 actual_output 或 assessment。保存模型名称、加载文件、实际输出和时间。评审者对照 must_preserve/must_not 逐项判定：

- 技术错误或权限越界：FAIL，并引用具体输出。
- 条件全部保留但仍有抽象表达或重复：表达未通过，指出句段。
- 材料不足且如实保留缺口：不算补全，但可以正确完成授权整理。
- 好句、规范术语、真实列表保持原样：可以通过，不要求改动。

比较版本时，固定模型、提示和材料，两个干净会话分别加载旧版和新版；由不知道版本标签的评审者比较结构、表达和事实保真。保真失败不能用文风收益抵消。真实项目验证另需用户授权材料；不要上传私有源码或完整日志来充当公开样例。
