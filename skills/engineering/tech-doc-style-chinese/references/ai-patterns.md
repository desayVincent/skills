# 表达模式检查

用于内部技术文档交稿前及去 AI 口吻任务。借鉴 humanizer 的结构模式，检查表达质量，不推断作者或生成概率。词频、标点和句长只是线索；不能单独作为缺陷。

## 检查方法

先看全文和段落是否推进问题，再看句子。每个疑点回答：它提供了什么信息？证据在哪里？删掉会损失什么？按「位置、具体问题、处理或保留理由」在工作记录中简记，仅按任务要求交付报告。

确定是空内容就删；承载事实就重写其完整句段；信息不足就保留归属及缺口。重读改稿时检查是否仍有相同结构问题，不为了清零命中反复改写。

## 模式与例外

| 模式与识别线索 | 改写操作 | 必须保留的例外 |
| --- | --- | --- |
| 无对象的意义拔高：「里程碑、重塑、全面升级」 | 写实际变化与影响，没有依据就去掉拔高 | 有明确验收定义的里程碑和正式名称 |
| 空性能评价：「显著、高效、稳定、无缝」 | 引用已有指标、基线与条件，缺证据则列明未验证 | 统计显著、有效位、稳定状态等准确用法 |
| 来源代替论据：「专家认为、业内普遍」 | 说明具体来源究竟支持什么，来源未知就保留归属待确认 | 用户给出的引用、原文与来源身份不能删成无归属事实 |
| 假对比：「不只是 X，更是 Y」且 X 无人主张 | 直接写 Y 中有信息的部分 | 两方案真实差异、纠正常见误解和规范性禁止 |
| 想象反方：「有人可能会说」却没有论证对象 | 去掉空辩解，保留确实讨论的选择与代价 | 真实评审异议、历史被否决方案和理由 |
| 主持开场：「接下来深入探讨」 | 直接进入本节问题或事实 | 真实导航提示、必要范围声明 |
| 重复收尾：「这才是真正的价值」 | 删除与上一段同义的评价 | 有新增后果、依赖或行动的结尾 |
| 套路展望：「仍有挑战，但未来可期」 | 写材料中具体限制、计划和批准状态 | 真实风险和已安排的后续工作 |
| 强凑三项或机械排比 | 合并同义项，让条数服从内容 | 三种真实状态、并列接口和验收项 |
| 段落可任意调换，各说一遍「重要」 | 按问题、支持、影响建立逻辑次序 | 独立参考条目和无序清单 |
| 标题换词后首句再次复述 | 让首句开始解释机制、约束或证据 | 首句提供定义或适用范围 |
| 术语轮换：「缓冲区、容器、载体」混指一物 | 恢复项目统一名称 | 不同层级的对象不能为统一而合并 |
| 句末附加「从而确保……」但缺因果依据 | 保留前面的事实，将后果按证据降为推断或待验证 | 已确认因果、保证条件和安全约束 |
| 「从 X 到 Y」拼凑虚假范围 | 分别写实际对象，不宣称覆盖中间全部 | 真实数值范围、版本跨度和完整流程 |
| 叠加模糊语气：「或许可能在某种程度上」 | 保留一层准确限定 | 通常、可能、最多、仅、尚未验证及资料截至日期 |
| 加粗、破折号、短标题覆盖每项 | 去掉无信息装饰，按含义选择句子、列表或表格 | 固定格式、警告强调、数值范围、公式、代码与链接 |
| 聊天残留：「好问题、希望有帮助、要我继续吗」 | 文件正文删掉包装，保留内容 | 对话记录、引用、用户要求的交互文案 |
| 占位符或聊天内部引用混入正文 | 能从给定来源还原时按授权修复，否则报告断链 | 稳定 ID、真实待确认项、模板本身；不编造来源或改 URL |

## 对照示例

### 假对比与真对比

原文：这不只是一个队列，更是系统协同的核心。队列保存待处理的帧地址。

改写：队列保存待处理的帧地址。

保留例外：队列保存帧地址，不复制帧数据。这里两部分都限定真实行为，必须保留。

### 三项不一定是问题

原文：模块提供创建、查询和销毁三个接口。

保持原样。不能为了避免排比删掉一个接口或合并成「生命周期管理」。

### 删除总结，不删结果

原文：重试耗尽后返回 EIO。这为系统可靠性奠定了坚实基础。

改写：重试耗尽后返回 EIO。

没有新增处理或证据的可靠性评价被删除；不能推断调用方一定恢复成功。

### 语义不确定性不能当成语气问题

原文：当前测试没有覆盖掉电恢复，恢复结果尚未确认。

保持原样。不能用「系统支持掉电恢复」替换，也不能因它像免责声明而删除。

## 不采用的检测思路

不以英语词长、句长波动、困惑度或固定标点推断中文作者；不人为加错字、故事、第一人称经历、强立场或生僻词。表达自然的依据是具体、连贯、准确，不是绕过检测器。上游模式及取舍记录在 upstream-sources.md，日常执行无需读取或联网。
