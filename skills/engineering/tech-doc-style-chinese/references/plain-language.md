# 表达修复

用于改写、去 AI 口吻和难懂表达。按症状选方法，不逐句强套。下列改写只使用给定原文或上下文；缺少具体对象时标明缺口，不猜接口或职责。

## 句子：识别 → 修复 → 保留例外

| 症状 | 操作 | 保留边界 |
| --- | --- | --- |
| 「进行……的配置与管理」等名词化 | 找动作及对象，改成动词；不同职责拆开说明 | 管理不一定等于配置，不能漏职责 |
| 「其、该过程、这一能力」指向不清 | 回到上下文确定对象，用已有名称替代 | 指向明确时可保留代词，未知时不补造主体 |
| 长定语包住多个条件和动作 | 先写对象，再写适用条件和动作；条件与对应动作放在一起 | 不改变条件覆盖范围、执行顺序或并发关系 |
| 只说「协同、编排、闭环」 | 依据材料说明实际调用、传递、状态变化或校验 | 闭环控制、内存对齐等正式术语不能按黑话删掉 |
| 「由……进行……」「被……所……」隐藏执行者 | 执行者已知且重要时，用执行者作主语 | 被动语态本身不是错误，责任未知不能猜 |
| 主谓不搭配或英文抽象直译 | 重写为对象的具体属性、约束或影响 | 「变得现实」不能仅换成「很重要」就算完成 |
| 专名轮换、动词混用 | 同一对象固定名称，按项目含义区分动作与状态 | 不把文件、记录、任务等不同对象合成一个概念 |
| 长串动作读不出时序 | 有顺序写编号步骤，并保留成功、失败和停止条件 | 无序并列不要写成依次执行 |
| 「可能会或许」重复限定 | 合并重复语气，保留必要的不确定程度 | 「通常」「仅」「最多」「可能」往往有技术含义 |
| 标题和首句重复、段落只起过渡作用 | 删除空引导，让下一句直接给信息 | 保留安全提醒、章节适用条件和真实阅读指引 |
| 长表格难以解释过程 | 可比较属性留表，机制移到相邻段落并引用 | 固定列、ID、引用和机器消费格式保留 |
| 短句过碎或一段堆多个问题 | 按一个主要问题合并相关句，分开无关句 | 不追求固定字数，也不人为制造长短交错 |

## 成组改写示例

### 1. 去掉名词化，不漏管理职责

原文：初始化时对读取方式进行配置，运行时对读取请求的取消进行管理。

改写：初始化时配置读取方式。运行时管理读取请求的取消。

保留：初始化与运行时是两种职责，不能压成「配置读取方式」。

### 2. 解释具体机制，不换抽象同义词

原文：任务通过 queue_send() 把帧地址交给处理线程，形成高效协同。

改写：任务通过 queue_send() 向处理线程发送帧地址。

保留：传递的是地址，不是整帧数据；没有证据支持「高效」，不补造等待、复制或所有权转移。代码排版按原文保持。

### 3. 拆条件与步骤

原文：在设备已停止且 DMA 不再访问缓冲区的情况下完成资源的释放并在成功释放后更新状态，若释放失败则保持原状态。

改写：设备已停止且 DMA 不再访问缓冲区时，释放资源。释放成功后更新状态；释放失败时保持原状态。

保留：两个前置条件都适用于释放；更新状态只在成功后发生。

### 4. 用已有名称消除指代

上下文：生产线程写入缓冲区，消费线程读取缓冲区。

原文：消费线程处理完成后通知生产线程，由其复用缓冲区。

改写：消费线程处理完成后通知生产线程，由生产线程复用缓冲区。

保留：没有把复用责任交给消费线程。

### 5. 保留未知责任

原文：错误被记录到日志中，记录者尚未确认。

改写：错误被记录到日志中，记录者尚未确认。

保留：被动句有用；不能为了主动语态写成「驱动记录错误」。

### 6. 翻译腔改成约束

原文：多个客户端共用同一个限流计数器，客户端间的影响变得很现实。

改写：多个客户端共用同一个限流计数器，限流计数会受到其他客户端请求的影响。

保留：不补造限流阈值、算法或解决方案。

### 7. 保留好的专业表达

原文：MAC 阵列每周期读取 16 个 INT8 数据。

改写：MAC 阵列每周期读取 16 个 INT8 数据。

保留：读取数量不是运算次数，INT8 不能替换成笼统的「数据」。

### 8. 精简重复限定

原文：超时后可能会有概率丢弃当前帧。

改写：超时后可能丢弃当前帧。

保留：不能删成「超时后丢弃当前帧」，也不能补出概率值。

### 9. 正文解释，列表比较

原文：读取失败后重试，最多重试 3 次，每次间隔 5 ms；仍失败时返回 EIO。

改写：读取失败后，最多重试 3 次，每次间隔 5 ms。重试后仍失败时返回 EIO。

保留：无需为这两句新建表格，不把次数理解为总请求次数。

### 10. 空评价缺少材料时不假装补足

原文：这个模块实现了稳定可靠的处理闭环。

改写建议：现有说明未交代处理步骤、失败行为或可靠性证据，需要补充后才能确认该评价。

保留：这是缺口说明，不是凭空生成替代架构。文件改写时保留必要主张归属，在交付说明列出缺口。

### 11. 条件限制不能改成额外等待

原文：仅在 DMA 停止后才允许释放缓冲区。

保持原样，或写「释放缓冲区的前提是 DMA 已停止」。不能写「超时后不能立即释放」：如果超时前 DMA 已停止，原文允许释放，改写却可能禁止。改写条件句时分别核对条件已满足与未满足两种情况。

## 完成检查

用目标读者的知识重读完整段落：对象是否明确，术语是否需要解释，条件能否对应动作，段落是否推进问题。若仍需猜测，重新组织解释，不仅换词或分行。没有证据可用时说明缺口，不靠更肯定的语气掩盖它。
